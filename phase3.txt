# PHASE 3 BUILD PROMPT
# Patient Progress Dashboard — SOFA, Vitals, Laboratory Reports,
# Radiology, Comparison and AI-Generated Progress Summary

============================================================
1. PROJECT OBJECTIVE
============================================================

Build Phase 3 of a hospital patient-progress application.

The purpose of Phase 3 is to allow authorized Doctors and Nurses to
select a patient_id and admission_id and view the patient's complete
progress over time.

The dashboard must combine:

1. Patient information
2. SOFA score and SOFA history
3. Vitals and vitals trends
4. Laboratory/report results and report trends
5. Radiology reports
6. Radiology images stored in Azure Blob Storage
7. AI-generated patient progress summary

The application must correlate all information using:

    patient_id
    admission_id
    date
    time
    report/test identifiers where applicable

The current implementation uses LOCAL files for testing.

Later:

    patient_reports.xlsx -> PostgreSQL
    vitals.csv           -> PostgreSQL
    sofa_scores.csv      -> PostgreSQL

The UI/data-access layer must be designed so that moving from local
files to PostgreSQL requires minimal code changes.

============================================================
2. USER ROLES / LOGIN
============================================================

There are different application roles.

PHASE 1 + PHASE 2:

    Hospital Admin
    Lab User

These users upload/process patient reports and vitals.

PHASE 3:

    Doctor
    Nurse

Doctors and nurses can view patient progress and analysis.

For Phase 3 implement role-aware access.

Only authorized Doctor/Nurse users should be able to access the
patient-progress dashboard.

Do not expose administrative upload functionality inside the Phase 3
dashboard.

Keep authentication/authorization modular so Azure Entra ID / RBAC
can be integrated later.

For local development, provide a simple mock authentication mechanism
or role selector.

7. SOFA SCORE ENGINE
============================================================

Implement a deterministic SOFA calculation engine.

SOFA consists of six organ systems:

    1. Respiration
    2. Coagulation
    3. Liver
    4. Cardiovascular
    5. CNS
    6. Renal

The SOFA engine must never determine a variable from a numeric value
alone.

It must:

    1. Match test_name
    2. Read result
    3. Read unit
    4. Validate/normalize unit
    5. Evaluate the correct SOFA rule
    6. Return the score and evidence

Evaluate each system from:

    Score 4
    Score 3
    Score 2
    Score 1
    Score 0

Take the first matching condition.

------------------------------------------------------------
7.1 RESPIRATION
------------------------------------------------------------

Variable:

    PaO2/FiO2 Ratio

Unit:

    mmHg

Rules:

    0: >400
    1: <=400
    2: <=300
    3: <=200 WITH respiratory support
    4: <=100 WITH respiratory support

Respiratory support is represented by a row in patient_reports.xlsx.

The exact test_name should be configurable.

If respiratory support is not positive, do not apply the support-dependent
Score 3 and Score 4 conditions.

------------------------------------------------------------
7.2 COAGULATION
------------------------------------------------------------

Variable:

    Platelets

Unit:

    x10^3/uL

Rules:

    0: >=150
    1: <150
    2: <100
    3: <50
    4: <20

------------------------------------------------------------
7.3 LIVER
------------------------------------------------------------

Variable:

    Bilirubin

Unit:

    mg/dL

Rules:

    0: <1.2
    1: 1.2-1.9
    2: 2.0-5.9
    3: 6.0-11.9
    4: >=12.0

------------------------------------------------------------
7.4 CARDIOVASCULAR
------------------------------------------------------------

Inputs:

    MAP
    Dopamine
    Dobutamine
    Norepinephrine
    Epinephrine

MAP source:

    vitals.map_mmHg

Vasopressor source:

    patient_reports.xlsx

Vasopressor unit:

    validate expected dose unit before comparison

Rules:

    0: MAP >=70
    1: MAP <70
    2: Dopamine <=5 or Dobutamine any dose
    3: Dopamine >5 or Norepinephrine/Epinephrine <=0.1
    4: Dopamine >15 or Norepinephrine/Epinephrine >0.1

Calculate the cardiovascular score independently from:

    MAP

and

    vasopressor data

Then use the WORST/HIGHEST applicable score.

------------------------------------------------------------
7.5 CNS
------------------------------------------------------------

Variable:

    GCS

Source:

    vitals.gcs

Rules:

    0: 15
    1: 13-14
    2: 10-12
    3: 6-9
    4: <6

------------------------------------------------------------
7.6 RENAL
------------------------------------------------------------

Inputs:

    Creatinine
    Urine Output

Creatinine source:

    patient_reports.xlsx

Urine output source:

    vitals.csv

Creatinine rules:

    0: <1.2
    1: 1.2-1.9
    2: 2.0-3.4
    3: 3.5-4.9
    4: >=5.0

Urine output:

    3: <500 mL/day
    4: <200 mL/day

If both creatinine and urine output are available:

    renal_score =
        max(creatinine_score, urine_output_score)

============================================================
8. SOFA FOUR-HOUR WINDOWS
============================================================

Calculate SOFA every 4 hours.

The windows are anchored to the patient's admission first recorded
observation.

Example:

    Admission start = 08:00

Windows:

    Window 1: 08:00 - 12:00
    Window 2: 12:00 - 16:00
    Window 3: 16:00 - 20:00
    Window 4: 20:00 - 00:00

Continue throughout the admission.

------------------------------------------------------------
8.1 CARRY-FORWARD RULE
------------------------------------------------------------

For each 4-hour window, select:

    The most recent known value at or before the window END time.

Example:

    Platelets at 09:00 = 123
    No platelet result at 12:00

For the 08:00-12:00 SOFA window:

    Use Platelets = 123

If the next result occurs at 15:00:

    The 12:00-16:00 window can use the 15:00 value.

Carry forward the most recent available value as long as it belongs
to the same patient + admission.

Do not use values from another admission.

------------------------------------------------------------
8.2 MISSING ORGAN SYSTEM
------------------------------------------------------------

If an organ system has never had any required value recorded as of
that SOFA window:

    Mark that organ system as NOT AVAILABLE.

Do NOT automatically assign score 0.

The UI must clearly show:

    Available
    Not Available / Missing

Only calculate/display a total SOFA score when there is enough data
according to the application's missing-data policy.

The calculation must preserve the difference between:

    "normal value"

and

    "no data available"
